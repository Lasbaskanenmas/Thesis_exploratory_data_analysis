**F1, model ranking within rgb weighted.** Friedman χ² = 15.075, df 3, **p = 0.00175**, Kendall's

**ConvNeXt over SegFormer is the only robust pairwise architectural claim** (15/16 routes, sign
p = 0.0005, rank-biserial +0.88). **ConvNeXt over resnet34 is FRAGILE** — rejects in primary, fails
both sensitivities. Swin, SegFormer and resnet34 are not separable; SegFormer vs resnet34 is a
near-perfect null (8/16, p = 1.0000, rb +0.06). **This narrows the handoff's F2** to the top of the
ordering and nothing below it.

**F2, channel effect within ConvNeXt.** Friedman **p = 0.30498**, W = 0.074 — **fails to reject, so
D1's rule downgrades the family narrative to descriptive.** No pair rejects. `rgb` vs `6ch` and `rgb`
vs `10ch` are nulls, the latter pointing *opposite* to the pooled figure. **The pooled
`RGB ≥ 10ch ≥ 6ch` ordering has no route-level support.** `6ch` vs `10ch` rejects only under
Sensitivity A → fragile.

**F3, weighting.** p = 0.7057, exactly 8/16 routes, rb +0.12. **A measured null.**

**The effective-N fear did not materialise.** All ten pairs have **n′ = 16 with zero exact ties** —
the low-diversity routes differ at order 10⁻⁴ rather than identically, so the classical zero-drop
removes nothing. D2 anticipated the mechanism. Sensitivity B's δ = 0.001 rule does the work,
taking n′ to 14–15.

**21 of 21 descriptive contrasts** have paired whole-route bootstrap CIs; six exclude zero. The arms
are **descriptive by declaration, never tested for significance** — that is D1, locked before their

**McNemar (context only).** 12,194,633,781 scored pixels — independently reproducing the pooled
figure exactly. All ten p-values 0.000e+00, as the declaration predicted. **Two pairs invert against

mass; macro-IoU weights nine classes equally. **This is the thesis's own metric argument
demonstrated on its own data** and belongs beside the F1 trivial-baseline exhibit.

### 4.5 E4 — first ever run, and it landed a headline

Full write-up in `2026-08-24_E4_label_quality.md`.

1. **The 37 % ignore mass is annotation COVERAGE, not annotator uncertainty.** Of everything becoming
   ignore, **94.20 % is the nodata sentinel**, 5.80 % explicit `unknown`, measured over all 799 parent
   rasters and 54.1 bn pre-tiling pixels. Cross-checked against the GeoPackage: 17,791 polygons,
   56.43 km², 29.21 % of the tile footprint. Effective supervised set ≈ 12.2 of 19.3 bn px.
2. **The ignore mask is severely biased by geography: 11.80 % (82-11) to 89.33 % (83-34)**, per fold

3. **Boundary-error profile**: error rate **42.17 % on an annotation boundary against 2.42 % at

   share cannot be edge imprecision and is the F5b class-confusion reading. Both mechanisms present
   and separable.

### 4.7 Metric breadth and Boundary IoU

**Metric choice reverses rankings.** `convnext_upernet_10ch` is third on macro-IoU but first on
FW-IoU and binary accuracy; `segformer_b1_10ch_unw` is 23rd of 27 on macro-IoU yet beats

**Boundary IoU became a finding, not just breadth.** At d = 28 px the nine classes split into four

two pre-registered qualitative modes.

## 8. Bugs and traps found — the most transferable part of this file

Every one of these was caught by an assertion or a check, not by luck. Several would have been
silently wrong.

1. **The ignore-index column convention.** `metric_breadth.py`'s first draft reimplemented scoring
   and dropped the ignore *column* as well as its row. The frozen convention keeps the column —
   predicting `unknown` on a real pixel is a false negative for that class. **Exactly one cell in 27
   does this** (`unet_resnet34_10ch_unw`, 14,671 px of 19.3 bn), so a private reimplementation would
   have matched on 26 cells and been silently wrong on the 27th. Fixed by delegating to
   `per_category_metrics.metrics_from_confusion`.
2. **`CUDA_VISIBLE_DEVICES=""` does not hide the GPU on Windows** — an empty environment variable is
   equivalent to an unset one. Use `"-1"`. Caught by an assertion that torch cannot see a device.
3. **`_unw` job naming.** Cell `convnext_upernet_rgb_unw` trained as
   `convnext_upernet_rgb_fold0_unw` — **the fold comes before the suffix**. Building
   `<cell>_fold<f>` silently points at a non-existent directory. (Agent 1 hit the same trap in E6.)
4. **git blob hashing and `core.autocrlf`.** `verify_git_backup.py` first hashed raw disk bytes
   against index SHA-1s. Git normalises CRLF → LF before writing the blob, so **every CRLF text file
   looked modified** — including 28 pooled JSONs untouched since July. Diagnosed on
   `oof_convnext_upernet_rgb` (disk 28,211 B / raw sha `c43c8ca6`; LF-normalised 26,888 B / sha
   `e28cee22` = the index). Now tests both forms.
5. **The Part B declaration schema.** The 25/8 addendum said the runner needed no code change. It
   did: the author's block uses `status: LOCKED` not a `locked_utc` timestamp, `families` as a
   *mapping*, `per_route_metric` as a mapping, flat route-rule keys. The runner **would have refused
   the real file on lock day**.
6. **The fragility rule.** First implemented as "primary Holm decision vs each sensitivity's *raw* p".
   D2 says "disagree in significance **after Holm**". The raw version flagged `cnx − swin` (not
   fragile) and **missed `cnx − rn34`** (genuinely fragile on a headline claim).
7. **Boundary IoU is size-insensitive** — a self-test assertion written the wrong way round. Under
   the same 1 px error, mask IoU improves as the object grows while Boundary IoU holds. That is the
   property the metric exists for.
8. **YAML parses an unquoted `2026-08-25` as `datetime.date`**, which `json.dumps` cannot serialise.
   Coerced in the runner rather than by editing the locked declaration.
9. **A topped-up pass-2 tile had no rendered panel**, silently dropping the double-scored share from
   12.5 % to 10.9 % while the provenance claimed 12.5 %.
10. **E6 writes are destructive.** It opens all three artifacts in `"w"` mode and writes only the
    cells passed to it. **Always run the full roster and snapshot first.** Pre-sweep snapshots from
    this agent: `results/tables/pre_e6_2026-08-27/`, `pre_e6_2026-08-31/`, `pre_e6_2026-09-07/`.
    Additivity was *verified*, not assumed, after every sweep — 0 differences among pre-existing
    rows each time.

**A premise that was wrong and cost a week.** On 27/8 the work order stated the two ConvNeXt arms
were "trained and inferred days ago". Disk said otherwise: no job folders, no `.pth`, no logs, no
predictions, no smoke. **Launch Blocks 1 and 2 had never been pasted** — the GPU had gone straight to
the 17/8 `6ch_corrected` blocks. **Verify completeness before scoring anything**: 10 epochs, a final
`.pth`, and prediction counts of exactly 6,439 / 6,437 / 6,438.
